# Анализатор учебных планов и коллизий кафедр (`plan_analyzer`)

Автономная Python-библиотека и десктопное standalone-приложение с нативным интерфейсом для комплексного анализа учебных планов (форматы **Шахты / MMIS dsMMISDB: `.plx`, `.xml`, zip**). Включает извлечение пар **«Дисциплина — Кафедра»**, поиск **коллизий кафедр**, анализ **форм контроля** (экзамены/зачеты), **нормативный аудит семестров ФГОС**, анализ **лексического и семантического подобия** дисциплин, управление **преподавателями и отраслями знаний**, а также **безопасное внесение изменений обратно в файлы планов**.

---

## 🌟 Ключевые возможности

1. **Пакетная обработка планов:**
   - Поддержка шахтинских файлов `.plx` (включая zip-архивы с XML внутри) и стандартных `.xml` схем `dsMMISDB`.
   - Загрузка как через нативный GUI / браузер (Drag & Drop), так и указанием пути к локальной папке на диске.
   - Возможность последовательного добавления и точечного исключения планов.

2. **Анализ форм промежуточного контроля и аудит семестров (ФГОС):**
   - **Межплановые коллизии форм контроля:** автоматический поиск дисциплин с одинаковым названием, у которых в разных планах различаются формы итоговой аттестации (например, в одном плане *«Экзамен»*, а в другом — *«Зачет»*).
   - **Нормативный аудит нагрузки семестров:** проверка соблюдения максимальных лимитов ФГОС ВО:
     - 🎓 **Экзаменов:** не более **5** в экзаменационную сессию;
     - 📝 **Зачетов:** не более **6** в семестр;
     - 📚 **Курсовых проектов / курсовых работ:** не более **2** за семестр.
   - Детализация по каждому семестру каждого плана с подсчетом суммы ЗЕТ и списка дисциплин с формами контроля.
   - Экспорт листа аудита семестров ФГОС в Excel в один клик.

3. **Дисциплина как центральная единица анализа:**
   - Каталог уникальных дисциплин с полными профилями (кафедры, планы, семестры, формы контроля, нагрузка в ЗЕТ и часах, индикаторы коллизий).
   - Привязка к каждой дисциплине **отрасли знаний** (например, *«Информационные технологии»*, *«Юриспруденция»*) и пула **преподавателей**.
   - Фильтрация каталога по отрасли, преподавателю, кафедре, году набора, учебному году и флагам коллизий.

4. **Управление справочниками (преподаватели и отрасли):**
   - Ручное добавление и редактирование через интерактивное модальное окно.
   - Пакетная загрузка справочников из файлов **Excel (`.xlsx`)** и **CSV**.
   - Загрузка готовых связок «Дисциплина — Отрасль — Преподаватели» из таблиц.
   - Персистентное сохранение всех привязок в локальном хранилище `data/registry_store.json`.
   - Экспорт полного реестра дисциплин и справочников в многостраничный Excel-файл (`.xlsx`) в 1 клик.

5. **Детекция и разрешение коллизий кафедр:**
   - Автоматический поиск ситуаций, когда одна и та же дисциплина в разных планах закреплена за разными кафедрами.
   - Фильтрация коллизий по году набора и конкретному учебному году (например, *«2025/2026 уч. год»*).
   - Определение рекомендуемой кафедры (по большинству планов).
   - Быстрое переназначение кафедры в 1 клик для всех планов сразу или выборочно.

6. **Анализ подобия дисциплин (Hybrid Similarity Engine):**
   - **Лексическое сравнение (RapidFuzz):** выявление опечаток (*«програмирование»* vs *«программирование»*), перестановок слов (*«Базы данных и СУБД»* vs *«СУБД и базы данных»*), различий римских/арабских цифр семестров и частей.
   - **Семантическое сходство (FastEmbed / ONNX):** компактная русскоязычная нейросетевая модель эмбеддингов (`paraphrase-multilingual-MiniLM-L12-v2`), работающая локально на CPU без PyTorch и интернета (*«Юридические вопросы»* $\leftrightarrow$ *«Юридические проблемы»* — сходство 97%).
   - **Поиск скрытых коллизий:** подсветка ситуаций, когда концептуально схожие дисциплины читаются разными кафедрами.
   - **Интерактивная унификация:** приведение схожих названий к единому каноническому виду с синхронизацией кафедры.

7. **Безопасная модификация шахтинских файлов (Diff & Staging):**
   - Предварительный просмотр всех подготовленных изменений (было $\rightarrow$ стало) перед физической записью.
   - Выбор режима сохранения:
     - Создание резервных копий оригинала (`.bak`) и перезапись на месте;
     - Запись измененных планов в отдельную директорию (`output/`).

8. **Standalone десктопное приложение:**
   - Нативное окно на базе `pywebview` (без адресной строки браузера и рамок поисковика).
   - Однокликовый запуск на macOS через `Запустить Анализатор.command`.
   - Полная сборка в автономный `.app` / exe бандл через `PyInstaller`.

## 🚀 Быстрый старт и запуск

### 1. Установка окружения

```bash
# Переход в каталог проекта
cd "Анализ УП"

# Установка зависимостей с помощью uv (рекомендуется)
uv pip install -e .
# или через стандартный pip:
pip install -e .
```

### 2. Запуск десктопного приложения (Нативное окно)

- **На macOS в один клик:** Дважды щелкните по файлу `Запустить Анализатор.command` в Finder.
- **Через терминал:**
  ```bash
  python run_desktop.py
  ```

### 3. Запуск веб-сервера в браузере

```bash
plan-analyzer ui
# или через python модуль:
python -m plan_analyzer ui
```

Интерфейс откроется в браузере по адресу `http://127.0.0.1:8000`.

### 4. Консольный анализ (CLI)

```bash
plan-analyzer analyze "demo_plans"
```

Выведет в терминал статистику планов, реестр пар и список коллизий.

## 💻 Использование как Python-библиотеки

Библиотека предоставляет простой объектно-ориентированный программный интерфейс:

```python
from plan_analyzer import PlanAnalyzer, PlanService, ChangeRequest

# 1. Анализ планов и коллизий
analyzer = PlanAnalyzer()
analyzer.load_directory("path/to/plans")

# Поиск коллизий кафедр
conflicts = analyzer.find_conflicts()
for c in conflicts:
    print(f"Коллизия в дисциплине '{c.discipline_title}': кафедры {c.departments}")

# Поиск коллизий форм контроля (экзамен vs зачет)
control_conflicts = analyzer.find_control_conflicts()
for cc in control_conflicts:
    print(f"Коллизия контроля в '{cc.discipline_title}': {cc.control_forms}")

# Аудит семестровой нагрузки по нормативам ФГОС
audits = analyzer.audit_semester_controls(max_exams=5, max_passes=6, max_course_works=2)
overloaded = [a for a in audits if a.is_overloaded]
print(f"Перегруженных семестров: {len(overloaded)}")

# 2. Сервисный слой для модификации файлов
service = PlanService()
service.load_from_directory("path/to/plans")

# Подготовка изменения (стейджинг)
diffs = service.stage_change(
    ChangeRequest(
        action_type="change_dept",
        discipline_title="Высшая математика",
        target_dept_code="15",
        target_dept_name="Кафедра высшей математики"
    )
)

# Применение изменений с созданием бэкапов .bak
result = service.apply_changes(backup=True)
print(f"Успешно изменено файлов: {result.modified_files_count}")
```

## 🧪 Тестирование

Проект полностью покрыт модульными и интеграционными автотестами:

```bash
pytest -v
```

Все **48 тестов** проверяют:
- Корректность парсинга шахтинских планов и извлечения семестровых форм контроля;
- Детекцию коллизий кафедр и форм контроля;
- Соблюдение и аудит лимитов ФГОС (экзамены, зачеты, курсовые);
- Расчет трудоемкости в ЗЕТ и академических годов;
- Работу векторных эмбеддингов FastEmbed и нечеткого поиска опечаток;
- Безопасную запись в файлы `.plx` (zip) и `.xml` без повреждения XML-схемы;
- Экспорт многостраничного отчета в Excel;
- Работу всех эндпоинтов REST API веб-приложения.
